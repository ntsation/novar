Use cases

What Telvax is good for, with a program for each case that you can run from the repository root. Every program below is in examples/ and is run by the commands shown.

1. Data analysis on tables

Section titled “1. Data analysis on tables”

A Table[Row] is an Arrow table whose columns are the fields of the type Row. The column names and types are checked before the program runs, and a column is read as a tensor without copying it.

Use it for reports, feature preparation and quick checks of a data file. A misspelled column (sales.prise) is a compile error (no column prise on type Table[Sale]) instead of a failure halfway through a run. SQL (and Parquet) need the full build; telvax-lite keeps tables in memory and reads CSV.

2. Models whose shapes are checked

Section titled “2. Models whose shapes are checked”

Tensor shapes are part of the type, so a matrix product of mismatched shapes does not compile:

Change the weights in layer1 to Tensor[f32, 4, 4] and telvax check reports matmul inner dimensions differ: 3 and 4 at the call. Use symbolic dimensions (Tensor[f32, N, 3]) when a size is only known at run time. Weights come from std.tensor.from_vec here; a real model would load them from a file or a table.

3. Serving a function over HTTP

Section titled “3. Serving a function over HTTP”

@endpoint turns a function into a route. The parameter type is the JSON body and is validated for you; Err(Status.BadRequest(...)) becomes a 400.

To ship it, telvax build --serve examples/service/sentiment.tvx -o service --dockerfile produces one binary with the program embedded, plus a Dockerfile.

6. Errors as values

Section titled “6. Errors as values”

There are no exceptions. A function that can fail returns Result[T, E] or T?, match must cover every case, and ? passes an error up to the caller.

7. Plain numeric code, interpreted or native

Section titled “7. Plain numeric code, interpreted or native”

Integers, floats, loops and types of your own also work as an ordinary language. The interpreter runs anything; the native backend (--features llvm) compiles the subset described in the README.

Beyond one file

Section titled “Beyond one file”
  • Several files and packages: from util import helper and tvpm, see the tour.
  • Many machines: std.dist.map with telvax worker, see the tour.
  • From Python: the python/ module exchanges Arrow tables and NumPy arrays without copying.
  • In the browser: the playground runs the checker and interpreter as WebAssembly.
  • Editor: telvax lsp and the VS Code extension give diagnostics, hover and completion.

When Telvax is not the right tool yet

Section titled “When Telvax is not the right tool yet”

It is an alpha. The native backend covers a small subset, PTX and StableHLO output has not been run on NVIDIA GPUs or TPUs, and syntax can still change. docs/design/status.md lists what was verified and how.
